# 1.0.1 — Git Flow governance

Source release for the Git Flow migration on 2026-11-12. This release changes repository workflow and automation; it does not deploy an application to production, TestFlight or AppStore.

- Develop becomes the integration/default branch. Features and bugfixes target develop; versioned releases and hotfixes target main and are backmerged.
- CI rejects invalid PR routes, stale task heads, missing release notes and feature additions during stabilization.
- Required approval is separated from non-bypassable CI/history protection. Only verified owner NV-DuyManh is exempt from approval; other contributors need another reviewer.
- PR #51 retains its author and commits and is retargeted to develop with a narrowly scoped transition exception expiring 2026-11-26. It is not included in this release.
- Automatic head deletion is disabled until release/hotfix backmerges are complete. Published source tags are immutable.
- Expo compatibility checks use the locked SDK's bundled metadata rather than mutable online recommendations; dependency validation, typechecks, Jest and browser checks stay enabled. No dependency versions change.

Validation: governance and Git Flow regression tests, local Git ancestry/conflict checks, and the required module CI checks for the actual feature/release/main revisions. Actual run results are recorded in the migration PRs; no app runtime code or database schema changes are included.

Rollback: revert a verified regression through a reviewed bugfix/hotfix PR. Server setting snapshots are retained locally outside Git; restoring those settings requires the owner's explicit instruction. Do not force-push shared branches or move published tags.
