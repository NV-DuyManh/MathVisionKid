# Phase 3.5.2 - Student Integration Finalization Report

## 1. Overview
The Student Mobile ↔ Spring Boot Integration is now complete, including the critical fix for the retry image upload flow.

## 2. Changes Made
*   **Backend Contract Fix**: We implemented a multipart form-data endpoint at `/api/v1/submissions/{id}/retry` in `StudentSubmissionController` and updated the `mathvision-api.yaml` OpenAPI contract.
*   **Backend Logic**: `SubmissionService.retrySubmission` now properly receives the `MultipartFile`, stores it using `ObjectStorageService`, creates a new `SubmissionImage` associated with the same `Submission`, clears previous validation hints, and resets the status to `PROCESSING` to maintain the audit trail.
*   **Backend Tests**: Fixed the `StateTransitionTest` which was failing with a storage error during `retrySubmission` testing by mocking `ObjectStorageService`.
*   **Frontend Integration**: Updated `SpringSubmissionService` and `MockSubmissionService` to use the updated `retrySubmission(id, uri)` signature and upload the file as a multipart request.
*   **Frontend UI & Privacy Gate**: 
    *   Completed the privacy mask editor (`privacy.tsx`), enabling the MOVE, RESIZE, and individual DELETE actions for masks.
    *   Wired up the flow from `Results (Needs Retake/Crop)` → `Camera` → `Crop` → `Privacy Gate` → `Preview` → `Processing`, ensuring that only the sanitized image is uploaded to the backend while preserving the `retrySubmissionId`.
*   **Known Issues Audit**: Verified that the previously reported HTTP 500 error on `/api/v1/auth/login` was merely an artifact of invalid JSON payloads generated by unescaped PowerShell `curl` commands, and the authentication endpoints behave correctly.

## 3. Validation

*   Backend REST calls accept proper multipart format and transition submissions to the correct next states.
